{{ _('5.4 Versioning') }}

{{ _('Authorised users only') }}

{% trans %}Versioning allows authorised users to create a new published record when the metadata for an existing instrument needs to be updated while preserving the previous record as part of the history of the instrument. This is useful when key descriptive, administrative, or lifecycle information changes, such as ownership, contacts, location, operational dates, measured variables, related resources, or other metadata that should remain traceable over time.{% endtrans %}

{% trans %}To create a new version, open the existing instrument record and select the option to Create a New Version. The system opens a new editable record based on the current instrument metadata, allowing the user to review, update, and submit the revised information. When the new version is published, the application generates a separate DOI for that version. Each published version is therefore independently citable, while remaining linked to the earlier and later versions of the same instrument record.{% endtrans %}

{% snippet 'help/snippets/figure.html', src='instrument-new-version.png', number='6', width=1874, height=1199, alt=_('An instrument record page with the Create a New Version action available in the record toolbar.'), caption=_('On the Instrument page, users can initiate the creation of a new version of the existing instrument.') %}

{% trans %}The link between versions is recorded through the Related Identifiers field. When a new version is created, the new record references the previous version using the relationship type IsNewVersionOf. This relationship makes the version chain explicit in the metadata and supports consistent DOI-based navigation between related instrument records.{% endtrans %}

{% trans %}The version history view provides a clear record of all versions associated with an instrument. Users can use this view to move between versions and understand how the record has changed over time. If a user opens an older version, the application indicates that it is not the latest version and provides a pathway to the current version. This helps prevent users from accidentally relying on outdated metadata while still keeping previous published versions accessible for citation, audit, and provenance purposes.{% endtrans %}

{% trans %}This versioning model preserves the distinction between the physical instrument and the metadata records that describe it. The instrument remains the same real-world object, but each published metadata version represents a specific state of knowledge about that object at a point in time. This approach supports DOI governance, long-term traceability, and transparent management of changes across the AuScope Instrument Registry.{% endtrans %}

{% trans %}See also DataCite version linkage for how this relationship is recorded in the published DOI metadata.{% endtrans %}
