{{ _('8.1 Taxonomy Search and Browse') }}

{% trans %}The Taxonomies interface serves as the centralised classification directory, providing users with structured navigation across all controlled vocabularies in the registry. The interface provides a dual-framework classification system to ensure data uniformity and support advanced asset discovery across multiple scientific sectors.{% endtrans %}

{{ _('8.1.1 Dual-Classification Framework') }}

{% trans %}The directory is divided into two distinct indexing architectures to balance localised asset tracking with standardised global discovery frameworks:{% endtrans %}

{{ _('Custom Taxonomies') }}
{{ _('Hierarchical dictionaries managed internally by the registry to support custom organisational tracking.') }}
{{ _('GCMD Taxonomies') }}
{{ _('Standardised environmental science keywords derived directly from the NASA Global Change Master Directory vocabulary service.') }}

{% trans %}Where possible, users are encouraged to request the addition of missing terms to the GCMD vocabulary rather than creating equivalent custom taxonomy terms.{% endtrans %}

{{ _('8.1.2 Search and Browsing Capabilities') }}

{% trans %}The interface offers multi-layered navigational tools designed to streamline how users locate specific terminology:{% endtrans %}

{{ _('Dynamic Vocabulary Search') }}
{{ _('Individual text search fields allow users to filter structural terms and pinpoint obscure classifications instantaneously.') }}
{{ _('Collapsible Tree Navigation') }}
{{ _('Interactive, multi-level dropdown hierarchies enable users to expand or collapse parent-child relationships between broader and narrower terms.') }}
{{ _('Incremental Data Loading') }}
{{ _('Large datasets utilise on-demand pagination controls, allowing public and registered visitors to expand sub-vocabularies without degrading page performance.') }}

{{ _('8.1.3 Facet Filtering and Classification Levels') }}

{% trans %}Both taxonomy frameworks organise system-wide terminology into three foundational classification streams to refine data entry and improve overall searchability:{% endtrans %}

{{ _('Instruments') }}
{{ _('Hardware classifications that index individual physical devices, sensors, and similar equipment.') }}
{{ _('Platforms') }}
{{ _('Structural terminology mapping out combined multi-device survey arrays, satellite configurations, and operational deployment networks.') }}
{{ _('Measured Variables') }}
{{ _('Granular physical properties, phenomena, or environmental metrics that the registered devices are explicitly configured to observe.') }}

{{ _('8.2 Create / Update / Delete a Taxonomy') }}

{{ _('Authorised users only') }}

{% trans %}The Taxonomies interface enables authorised users to create, expand, and modify hierarchical controlled dictionaries. This section provides a step-by-step workflow for establishing a new taxonomy registry and organising structured terms within it.{% endtrans %}

{% trans %}Initiating a fresh classification dictionary requires a high-level registration process. To create a completely new taxonomy structure:{% endtrans %}

  1. {% trans %}Navigate to the Taxonomies page from the main header and click the + New Taxonomy button.{% endtrans %}
  2. {{ _('Title') }} {{ _('Input a human-readable title that clearly establishes the scope of the controlled vocabulary.') }}
  3. {{ _('Name') }} {{ _('Provide a unique system name. If left blank, the application will automatically generate this string from your title entry.') }}
  4. {{ _('URI') }} {{ _('Users can optionally provide a custom, resolvable external URI to link this entry with broader vocabulary services. If left empty, the registry automatically mints a local, fully resolvable system URI.') }}
  5. {% trans %}Click Create Taxonomy to commit the record.{% endtrans %}
{% snippet 'help/snippets/figure.html', src='taxonomy-create.png', number='14', width=1849, height=966, alt=_('The New Taxonomy form, with fields for title, name and URI.'), caption=_('Creating a new Taxonomy interface.') %}

{{ _('Adding taxonomy terms') }}

{% trans %}Once the parent taxonomy is generated, users can populate it with precise, multi-layered scientific terms. The registry supports deep hierarchical structuring, allowing terms to be nested safely within one another for complex data classification:{% endtrans %}

  1. {% trans %}Open your created taxonomy from the list view and click the + Add Child Term button.{% endtrans %}
  2. {{ _('Label and Description') }} {{ _('Enter the explicit scientific term label along with a concise description detailing its metadata application boundaries.') }}
  3. {{ _('URI and Extras') }} {{ _('Just like the parent taxonomy, a resolvable URI is auto-generated upon saving unless a custom URI is manually supplied. Optional metadata properties can be added as a raw JSON object within the Extras block.') }}
  4. {% trans %}Click Create Term to finalise registration.{% endtrans %}
{% snippet 'help/snippets/figure.html', src='taxonomy-term-create.png', number='15', width=1855, height=1297, alt=_('The New Taxonomy Term form, with fields for label, description, URI and a JSON extras block.'), caption=_('Creating a new Taxonomy Term interface.') %}

{{ _('Editing and removing terms') }}

{% trans %}Controlled dictionaries are designed to be dynamic and can change as new geoscience sectors or instrumentation standards evolve:{% endtrans %}

{{ _('Modifying Metadata') }}
{{ _('Authorised administrators can select any active tree layer and click the Edit button to alter descriptive labels, adjust parental nesting structures, or append structural JSON key-value pairs.') }}
{{ _('Removing Classifications') }}
{{ _('To completely remove a taxonomy or a specific nested branch from the active workspace, click the red Delete button.') }}
