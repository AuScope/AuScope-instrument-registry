{{ _('7.1 Parties Search and Browse') }}

{% trans %}The Parties interface provides a simplified, lightweight way to quickly explore administrative stakeholders, equipment manufacturers, funding institutions, and technical contacts across the AuScope network.{% endtrans %}

{% snippet 'help/snippets/figure.html', src='party-search.png', number='10', width=1847, height=1662, alt=_('The Parties browsing page, with a single search bar, an Order by dropdown and organisation cards showing instrument and member counts.'), caption=_('Simple Party browsing and search interface.') %}

{% trans %}Users can search the registry using a single text search bar that scans the database for keyword matches in organisation names and basic metadata. Search results can be ordered using the "Order by" dropdown menu to sort the organisation profiles alphabetically by name. Each matched profile is presented with key metrics, including the total number of registered instruments and registered Party members. This repository utilises underlying CKAN Groups, allowing users to consolidate datasets, coordinate project teams, and organise published metadata by organisational themes.{% endtrans %}

{{ _('7.2 Create / Update / Delete a Party') }}

{{ _('Authorised users only') }}

{% trans %}Authorised users can create a new Party profile using the Add Party form. The interface presents a structured set of fields that capture the essential administrative and descriptive attributes of an organisation or individual. The layout mirrors the design patterns used across the registry, grouping related metadata into logical sections.{% endtrans %}

{{ _('The Party creation form includes:') }}

{{ _('Name and Identifiers') }}
{{ _('The primary Party name, optional aliases, and external identifiers such as ROR IDs.') }}
{{ _('Roles') }}
{{ _('A selectable list of roles (e.g., Owner, Manufacturer, Funder) that define how the Party participates in the lifecycle of instruments and platforms.') }}
{{ _('ROR search behaviour') }}
{{ _('The scope of the ROR organisation search depends on the selected Party roles. When the Party is assigned the Owner and/or Funder role, the ROR search is limited to registered organisations within Australia. If the Manufacturer role is selected, the ROR search is expanded globally to allow manufacturers from outside Australia to be identified and linked.') }}
{{ _('Hierarchy and Organisation Type') }}
{{ _('Optional fields for parent-child organisational relationships and classification of the Party as a university, government agency, company, or individual.') }}
{{ _('Location and Contact Details') }}
{{ _('Country, state, website, and contact information to support accurate attribution and external linking.') }}
{{ _('Short Description') }}
{{ _('A concise summary describing the relevance of the Party to the AuScope network.') }}

{% trans %}The form uses controlled vocabularies and dropdown selectors to maintain consistency across the registry. Once all required fields are completed, users submit the record using the Add Party button, which creates a new reusable Party entry.{% endtrans %}

{% snippet 'help/snippets/figure.html', src='party-create.png', number='11', width=1938, height=3380, alt=_('The Party creation and editing form, with fields for name, identifiers, roles, hierarchy, organisation type, location and description.'), caption=_('Party creation and editing interface.') %}

{{ _('Updating a Party') }}

{% trans %}Existing Party records can be edited by authorised users to reflect organisational changes, updated contact details, or expanded role assignments. The update interface mirrors the creation form, allowing users to adjust any metadata field. This ensures that Party profiles remain accurate and aligned with current institutional structures.{% endtrans %}

{% snippet 'help/snippets/figure.html', src='party-manage.png', number='12', width=1856, height=1245, alt=_('A Party profile page with the Manage button highlighted at the top of the form.'), caption=_('To manage an existing Party, click the "Manage" button at the top of the form.') %}

{{ _('Deleting a Party') }}

{% trans %}Existing Party records can also be deleted from the Manage section of the Party. The delete function is available at the end of the Party management form through the Delete button.{% endtrans %}

{{ _('Deletion is restricted.') }} {% trans %}Deletion permissions are restricted to protect references between Parties and to registered instruments or platforms. A CKAN system administrator can delete any Party record. AuScope administrators can create Parties and can delete only the Parties they created themselves.{% endtrans %}

{% trans %}Even where deletion is permitted, the system prevents removal if the Party is currently assigned to instruments. In this case, the Delete button remains visible, but the system displays an error advising the user to first remove or correct the existing references before the Party can be deleted.{% endtrans %}
